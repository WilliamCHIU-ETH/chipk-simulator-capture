# ChipK Simulator Capture Agent Guide

This repository is the optional, standalone material provider for Marketing Video. It owns
ChipK route selection, Simulator acquisition, recording recipes, runtime verification,
ChipK-specific phone-presentation semantics, and the versioned CLI/JSON boundary. Its accepted
Product Core is defined in `docs/product-core.md`.

Marketing Video owns fallback policy, Project/Revision/Asset/Timeline, narrative and scene-level
composition, final rendering, and delivery. Capture owns the phone-local focus, gesture, crop,
zoom/pan intent, and safe framing needed for ready-to-place mobile material. Request/Result v1 still
publish only screenshots or raw recordings with evidence. Contract v2 advertises one reviewed
prepared-video vertical slice; never extend that claim beyond its advertised profile, route, and
stock.

Marketing Video may execute this provider as a subprocess. The provider must never import or
reach back into Marketing Video source.

## Source-only rule

Git contains only material that a clean clone needs to understand, build, test, or operate the
provider's stable behavior: source code, schemas, architecture, rules, tests, sanitized
deterministic fixtures, the reviewed operational catalog, and recording recipes.

Keep a value out of Git when it is generated by capture, recording, OCR, a test, a build, a
Simulator, a device, an account, a session, a specific run, or a local machine. This includes
screenshots, video, PDF, manifests, action traces, OCR output, logs, caches, build products,
session state, credentials, real persona identifiers, actual secure-store locators, private
network addresses, internal endpoints, and user-specific absolute paths.

Use the ignored repository-local `.runtime/` directory for local configuration and outputs.
Unknown new file types go there first. Promote one into Git only after showing that a clean clone
needs it and completing a sanitization review. Do not delay ordinary runtime work to enumerate
every possible extension.

Platform contract paths and defensive source that names process, Keychain, session, or secret
concepts are allowed when they contain no machine/user-specific value. Public product route hosts
are allowed; private or internal hosts are not.

`npm run scan:source-only` inspects both tracked index blobs and the worktree. It must reject
force-added ignored artifacts as well as legacy artifacts already staged for a commit.

## Stable process boundary

The only canonical consumer commands are:

```bash
chipk-capture capabilities --json
chipk-capture acquire --request <absolute-json-file> --json
```

`chipk-capture-machine doctor --json` is the canonical side-effect-free operator environment
probe. It is control-plane tooling, not a third MaterialAcquisitionPort operation. The optional
machine launcher may call `acquire` only after doctor is READY and the current invocation supplies
explicit acquisition authorization. It automatically rechecks the dedicated device and delegates
VIP truth only to a clean pinned Provider that advertises fail-closed verification before any
mutation. An older Provider without that capability must return typed human action before acquire;
the launcher must never persist authorization/session claims or synthesize unsupported proof.

Request/Result v1 and v2 are separate closed schemas under `contracts/`. Artifact paths in a result
are POSIX paths relative to the caller-owned `outputDirectory`; absolute artifact paths never cross
the Port. For video workflows, the canonical consumer default is the advertised v2
`prepared-video` operation. Direct helpers plus manual ingest are not a stable consumer path.
Provider-local Simulator selection and run attestations come from the documented environment
contract, not from Marketing Video imports.

The direct route and recording helpers under `scripts/` remain provider-local operator and
diagnostic entrypoints. They are not an alternative Marketing Video Port.

## Runtime safety

- Use only reviewed route IDs in `config/simulator-capture.catalog.json`.
- Require one exact Simulator UDID, a dedicated device attestation, explicit run authorization,
  and an active approved VIP-session attestation before mutation.
- Never overwrite an output. A failed run publishes no partial final bundle.
- Never automate credentials, MFA, CAPTCHA, purchase, trading, external messaging, or destructive
  account actions.
- Tests and CI must not call Simulator, network, Keychain, or paid providers.
- Do not run actual capture or recording unless the user explicitly requests that runtime action.

During migration, this repository is the only writer for Capture source. The old app copy remains
recoverable until standalone and Marketing adapter validation pass, then it may be archived by the
Marketing repository owner.
